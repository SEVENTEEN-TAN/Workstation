## 状态

2026-09-23：用户已批准对话中的设计方向；本文是待用户审阅的书面设计。书面设计获批前不编写实施计划、不修改业务代码。

本文覆盖功能优化 TODO 的 D1–D5、E2、E3。它不代表功能已实现、已合并、已部署或已完成线上验收。

## 目标

用最少的新机制补齐已经存在但没有形成操作闭环的功能：重复行动在完成后真正生成下一次行动；知识库和在线简历拥有稳定前台入口；草稿转换后直接定位新动态；后台解释内容会出现在哪里、还缺什么步骤；首页项目源数据变化时明确提示并由管理员确认同步。

成功标准：

- 每日／每周重复行动只在第一次由非完成状态变为完成时派生一条下一行动，重复请求不会生成多份。
- 派生保留历史，不改变 KR 进度，不因重新打开旧行动而删除已经生成的下一行动。
- 前台导航可进入知识库；即使没有 PDF，用户仍能进入在线简历。
- 周报、里程碑和职业时间线转换成功后直接打开对应职业动态编辑态。
- 后台公开状态说明同时回答“是否会展示”“展示在哪里”“还需执行什么步骤”。
- 首页选中的项目源记录发生变化时显示待同步提示；管理员确认后只更新首页工作副本，仍需保存草稿和明确发布。
- OKR 新建和编辑弹窗通过桌面、手机及长表单的真实浏览器验收。

## 已确认边界

- 阶段 3 拆成三个可独立验收的实施包：3A 重复行动，3B 入口与操作闭环，3C 项目同步提示。
- D2 只做浏览器验收。已有居中修复不重复实现；只有验收发现具体缺陷时才进入单独修复流程。

- 不合并、不部署、不修改生产数据；阶段完成后只提交并推送当前功能分支。

## 总体架构

```text
3A 重复行动
完成旧行动 ──事务──> 更新完成状态 + 幂等派生下一行动

3B 入口与操作闭环
固定公共入口 ──> 知识库 / 在线简历
草稿转换成功 ──> /admin/activities?activity=<id> ──> 打开编辑态
共享公开判断 ──> 展示位置 + 剩余步骤

3C 项目同步提示
已保存首页快照 + 最新项目物化结果 ──比较──> 待同步项目
管理员确认 ──> 更新首页工作副本 ──> 保存草稿 ──> 明确发布
```

三个实施包不共享新的基础设施。它们只复用当前服务、路由、组件和首页草稿边界，因此可以分别测试、审查和提交。

## 3A：重复行动生效

### 触发条件

只在以下条件同时满足时派生下一行动：

1. 旧记录状态不是 `DONE`；
2. 本次更新后的状态是 `DONE`；
3. 更新后的 `recurrenceType` 是 `DAILY` 或 `WEEKLY`；
4. 当前行动还没有成功派生过下一行动。

编辑已完成行动、重复提交 `DONE`、把行动重新打开后再次完成，都不能再派生第二份。普通 `NONE` 行动只更新自身。

### 数据模型与幂等

在 `ActionItem` 增加可空自关联来源及来源记录上的派生标记，并明确使用 `SetNull` 保留派生历史：

```text
generatedFromActionItemId String? @unique
generatedFromActionItem   ActionItem? @relation("ActionItemRecurrence", fields: [generatedFromActionItemId], references: [id], onDelete: SetNull)
generatedActionItem       ActionItem? @relation("ActionItemRecurrence")
hasGeneratedNext          Boolean @default(false)
```

派生行动记录来源行动 ID。数据库唯一约束阻止并发创建多份，来源记录上的 `hasGeneratedNext` 则在派生行动被删除后保留“已经派生过”的事实。删除 KR 时沿用现有级联删除；删除单个来源行动时，派生行动作为普通历史记录保留，因此自关联的删除行为必须清除来源引用而不是删除派生记录。

状态更新与派生创建放在同一数据库事务。任一步失败时两者一起回滚，不能出现“已经显示完成但下一行动丢失”的半完成状态。

测试仓库接口需要提供与生产事务等价的单次操作入口，避免单元测试只验证两次彼此独立的模拟调用。

### 派生字段

下一行动复制：

- `keyResultId`
- `titleZh`
- `titleEn`
- `sortOrder`
- `recurrenceType`
- `recurrenceInterval`
- `recurrenceDays`

下一行动固定为 `TODO`，`completedAt` 为空，`generatedFromActionItemId` 指向来源行动。它不创建 KR 进度更新，也不改变 KR 的当前值、手工进度或状态。

### 日期和时区

业务时区固定为 `Asia/Shanghai`。日期计算使用上海日历日期，不使用服务器本地时区，也不按 24 小时毫秒直接累加。

锚点日期：

- 来源行动有 `dueDate`：使用该截止日的上海日历日期；
- 来源行动无 `dueDate`：使用本次首次完成时间的上海日历日期。

生成的截止时间沿用项目对日期字段的现有标准化方式；实施计划必须先以现有 OKR 日期输入、序列化和显示测试锁定具体 UTC 表示，不能另造一套日期格式。

### DAILY 规则

下一个截止日是锚点日期增加 `recurrenceInterval` 个上海日历日。间隔最小为 1，继续复用现有验证器。

### WEEKLY 规则

`recurrenceDays` 的 `1–7` 表示周一至周日，并先排序去重。算法：

1. 在锚点所在周内寻找锚点之后最近的选中星期；
2. 若存在，使用该日期；
3. 若不存在，移动到 `recurrenceInterval` 周后的目标周，使用该周最早的选中星期。

例如每 2 周、周一和周四重复：周一完成时下一次是同周周四；周四完成时下一次是两周后的周一。这样“间隔”控制跨周周期，不跳过同一周期内尚未发生的选中日。

### 重开和删除

- `DONE → TODO/IN_PROGRESS` 只清空旧行动的 `completedAt`。
- 已经派生的下一行动保持不变。
- 再次完成旧行动时通过 `hasGeneratedNext` 跳过派生，不新建。
- 编辑旧行动的标题或重复规则不追溯修改已派生行动。
- 删除已派生的下一行动后，来源行动的 `hasGeneratedNext` 仍为真；即使重开旧行动再完成也不会静默重建。若未来需要“补生成”，应另设明确操作，不纳入本阶段。

## 3B：入口与后台操作闭环

### 知识库固定入口

公共导航增加 `/knowledge`。沿用现有导航视觉和响应式行为，不为知识库复制新的菜单组件。入口指向现有知识库首页，由该页面继续承载文章、搜索、标签和主题合集。

### 在线简历独立入口

首页在线简历入口始终指向 `/resume`，不再依赖中文或英文 PDF 是否存在。PDF 状态只控制简历页面或首页中明确的下载按钮：有对应公开文件才显示下载；没有文件时仍可浏览在线简历。

这项修改不放宽简历文件公开规则，也不伪造下载链接。

### 转换后定位目标

三个转换工作区在接口成功后读取返回草稿的 `convertedActivityId`：

- 周报草稿；
- OKR 里程碑草稿；
- 职业时间线草稿。

转换成功且 ID 存在时导航到：

```text
/admin/activities?activity=<convertedActivityId>
```

真实页面文件位于路由分组 `src/app/admin/(workspace)/activities/page.tsx`，公开 URL 仍是 `/admin/activities`。

职业动态页面读取 `activity` 查询参数，并只在该 ID 存在于当前已加载记录时打开对应编辑态。参数缺失、格式错误或记录不可见时保持正常列表，不猜测记录、不发额外泄漏信息；可以显示普通的“未找到目标动态”反馈，并清理或忽略无效参数。

转换接口失败、没有 `convertedActivityId` 或转换返回未完成状态时，不跳转，保留当前草稿和已有错误提示。

### 展示去向与生效步骤

扩展现有 `PublicReadiness`，不建立第二套公开规则。组件继续接收共享判断产生的 `issues` 和 `notes`，并增加由调用方提供的静态上下文：

- 展示位置；
- 满足条件后是即时展示，还是需要保存／发布；
- 管理入口或下一步动作说明。

调用方只描述流程，不重新判断内容是否公开。建议文案边界：

| 模块 | 展示去向 | 生效步骤 |
| --- | --- | --- |
| OKR | `/okr` | 记录满足共享公开条件后由前台读取，无首页发布步骤 |
| 项目 | 项目页；被首页选中时也进入首页卡片 | 项目公开后即时进入项目页；首页卡片变化还需同步首页工作副本、保存草稿并发布 |
| 经历 | `/experience` 和首页相关区块 | 满足共享公开条件后由前台读取，无首页发布步骤 |
| 职业动态 | 首页当前动态／相关公开页面 | 满足共享公开条件后由前台读取，无首页发布步骤 |
| 能力域 | 首页能力区块 | 满足共享公开条件后由前台读取；部分技能或证据可能被省略 |
| 简历 | `/resume`；公开 PDF 另提供下载 | 在线简历入口固定存在；文件下载需文件本身公开且可用 |
| 配置类模块 | 不直接公开 | 明确说明它只影响后台行为或其他模块，不强行描述为前台内容 |

说明文本不得包含文件系统路径、哈希、密钥或内部错误堆栈。

### OKR 弹窗浏览器验收

对新建和编辑弹窗分别验证：

- 桌面视口水平、垂直居中；
- 手机视口不溢出屏幕，顶部和底部保留可操作空间；
- 长表单在弹窗内部滚动，背景页面不滚动；
- 遮罩点击行为符合当前产品约定；
- `Escape`、关闭按钮和取消操作可用；
- 打开后焦点进入弹窗，关闭后焦点回到触发元素；
- 新建与编辑状态均不因内容高度改变而偏移。

若发现缺陷，先记录可复现视口、操作和截图，再做最小 CSS／焦点修复并补对应检查；不能因为本地已有修复就提前勾选 D2。

## 3C：首页项目同步提示

### 判定来源

`HomeWorkspace` 已同时持有已保存内容 `savedContent` 和当前工作副本 `content`，首页项目工具已提供 `materializeHomepageProjects()` 与预览版本。阶段 3 复用这些对象，不保存新的同步状态表。当前预览和保存流程会自动物化最新项目，必须一并改为明确同步，否则确认按钮无法约束实际生效。

判定分两层：

1. 用 `savedContent.selectedProjectIds` 和最新项目记录生成权威候选快照；
2. 按项目 ID 对比 `savedContent.zh/en.projects` 中对应卡片与候选卡片的实际展示字段；
3. 同步按钮按当前工作副本的 `selectedProjectIds` 再计算一次，避免覆盖用户刚改的选择或顺序。

比较字段只包含当前物化函数产生的字段：`slug`、`image`、`category`、`title`、`description`、`tags`、`alt`。排序由 `selectedProjectIds` 决定，不用 JSON 全对象字符串比较，也不比较无关元数据。

### 状态分类

- **已同步**：保存快照与最新物化结果一致。
- **待同步**：源项目仍可公开，但一个或多个展示字段不同。
- **不可同步**：选中项目不存在、不再公开或不满足项目公开校验。沿用现有保存错误，不用旧数据静默覆盖。
- **工作副本已修改**：当前 `content` 与 `savedContent` 已不同。同步操作必须合并到当前工作副本，不能把其他未保存编辑还原掉。

界面显示变更项目名称和简短字段摘要，例如“标题、封面、描述已更新”；不实现逐字段 diff 编辑器。

### 同步操作

“同步项目更新到工作副本”执行现有项目物化逻辑，只替换当前工作副本的 `zh.projects` 和 `en.projects`，保留：

- 其他首页文字、链接和图片修改；
- `selectedProjectIds` 及顺序；
- 当前编辑视图、语言和设备预览状态。

同步前，内嵌预览显示当前工作副本中的项目卡片，不自动物化最新源记录。同步后页面进入未保存状态，预览立即显示新卡片。项目选择或排序操作则在同一次用户操作中物化工作副本卡片，以保留现有即时预览体验。同步不会调用保存 API，也不会发布。管理员仍需依次执行“保存草稿”和“发布”。

保存草稿时，服务端使用最新源项目重新物化作校验：若提交卡片与最新结果不同，拒绝保存并提示重新检查／同步，不静默替换提交内容。这样源项目在管理员同步后再次变化时也不会被无意带入草稿。正式发布仍只使用已保存快照。

项目列表由现有 `/api/admin/projects` 刷新；后台“检查项目更新”明确获取最新列表，并保留其他未保存首页内容。只依靠页面初始加载的数据无法发现另一个标签页刚修改的项目。

若项目不可同步，按钮禁用并提供项目模块入口；修复源项目后重新加载或刷新后台数据再判断。

### 不新增自动同步

项目更新时不反向写所有首页版本，不在项目保存事务中修改首页，不建立事件队列。这样保留历史版本的真实快照，也避免编辑项目时意外改变已发布首页。

## 错误处理与反馈

- 重复行动事务失败：当前行动和派生行动都不落库，返回现有 API 错误形状。
- 重复行动唯一约束竞争：读取已存在派生并把本次完成视为幂等成功；其他约束错误照常失败。
- 转换成功但跳转失败：转换结果已经存在，当前工作区显示新动态 ID 和“打开动态”入口，避免用户误以为转换失败并重复提交。
- 无效动态查询参数：不打开错误记录，不泄露是否存在无权访问的记录。
- 项目物化失败：不改工作副本，显示现有公开性或完整性原因。
- 公开说明：流程文案和共享规则结果分开展示，避免静态文案掩盖真实阻塞项。

## 测试与验收

### 3A 自动化

- `NONE` 行动完成不派生。
- DAILY 有／无截止日的日期计算。
- WEEKLY 同周下一选中日、跨周间隔、星期排序去重。
- 非 `DONE → DONE` 不派生。
- 重复请求、重开后再次完成、并发完成只保留一条派生。
- 派生字段正确，KR 进度不变化。
- 更新或创建失败时事务整体回滚。
- 上海时区跨日、跨月、跨年边界。

### 3B 自动化与浏览器

- 公共导航包含知识库入口。
- 无 PDF 时 `/resume` 入口仍存在；下载按钮仍按公开文件状态控制。
- 三类转换成功都导航到带编码 ID 的 URL；失败不导航。
- 有效查询参数打开正确动态；无效参数保持列表并安全反馈。
- `PublicReadiness` 展示去向、步骤、问题和说明，且不复制公开判断。
- D2 完成既定桌面、手机和长表单浏览器矩阵并保存证据。

### 3C 自动化与浏览器

- 无变化时不提示。
- 单个和多个项目变化时列出正确项目及字段摘要。
- 不可公开或缺失项目禁止同步。
- 同步只替换项目卡片，不覆盖其他未保存首页内容。
- 同步后预览更新、脏状态成立；保存前正式首页不变。
- 未同步前预览保持工作副本卡片；保存其他首页字段不会顺带同步项目。
- 同步后源项目再次变化时，保存拒绝过期卡片并要求重新同步。
- 保存草稿后仍不影响正式首页；明确发布后正式首页更新。

临时数据库必须使用明确的工作区内临时路径并在验证后删除。文档分别记录本地通过、提交、推送、合并、部署和线上验收，不能把前者写成后者。

## 实施拆分与顺序

书面设计批准后，分别编写三份实施计划：

1. **Stage 3A**：D1 重复行动。先做，因为包含数据模型、迁移、事务和最高的数据一致性风险。
2. **Stage 3B**：D2、D3、D4、E2、E3。入口、跳转和说明共享前后台导航上下文，但不依赖 3A。
3. **Stage 3C**：D5 项目同步提示。最后复用已经稳定的首页工作副本与发布边界。

每个实施包形成独立、可测试、可审查的提交；阶段集中验证通过后更新 TODO 和执行记录，并推送 `feat/homepage-visual-editor`。不自动合并或部署。

## 明确不做

- 不做通用低代码平台、自由布局、任意 HTML/CSS/脚本。
- 不做项目到首页的自动发布或双向同步。
- 不让首页编辑器直接修改项目源记录。
- 不为转换结果新建第二套详情页或通知系统。
- 不让重复行动自动更新 KR 进度。
- 不回溯修改已经派生的行动。
- 不把配置类后台模块包装成公开页面。
- 不在没有真实浏览器证据时把 D2 标为完成。
