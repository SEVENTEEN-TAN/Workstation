# 真实首页可视化编辑器设计

## 状态

2026-09-22：用户已确认继续，书面设计已批准；实施计划待审阅。

本文档是阶段 2（B1–B9）的修订设计。它不修改业务行为，不代表功能已实现、已合并或已部署。2026-09-21 的原设计和实施计划保留为历史记录，不回填或改写。

## 目标

将 `/admin/home` 从“预览在上、完整表单在下”改为一个面向首页维护的专用低代码工作区：左侧是页面结构，中间是与正式首页同构的真实渲染，右侧是当前选中内容的设置。管理员直接在页面原位修改文字，在右侧精确修改链接目标和图片；高级表单继续作为完整、可访问的备用入口。

成功标准：

- 预览与正式首页使用同一套 `HomeExperience` 组件和公开数据过滤规则，显示动态、项目、能力、经历及简历入口，不出现后台导航壳。
- 首页快照中的可见文字可以在页面原位选择和修改；中文输入法、换行、切换语言和 iframe 重载不会丢失未保存内容。
- GitHub、邮箱、人物图和二维码可以从右侧设置精确修改；图片复用现有媒体库。
- 可视化编辑只改变浏览器内工作副本；保存进入草稿，发布后才影响正式首页。
- 动态、能力、经历和简历状态只读取公开业务数据，不能在首页画布里被误写回源模块。
- 预览不可用时，管理员仍可通过高级表单完成维护和恢复。

## 已确认边界

- 这是首页专用编辑器，不建设通用页面搭建平台。
- 继续使用唯一的双语 `SiteVersion.content` 快照和现有保存、发布、版本历史、恢复为草稿流程。
- 文字采用页面原位编辑；链接目标和图片采用右侧设置面板。
- 高级表单保留，不删除现有字段维护能力。
- 本阶段只覆盖 B1–B9。C1–C5 的撤销重做、区块增减、排序、布局模板和结构化内容扩展没有获得实施批准。
- 不允许任意 HTML、CSS、脚本、组件、自由定位或远程图片 URL。

## 总体架构

阶段 2 不增加数据库表或第二套内容系统。页面编辑状态仍由 `HomeWorkspace` 单点持有：

```text
已保存草稿 ──> HomeWorkspace 工作副本 ──> 受控 postMessage ──> 真实首页 iframe
                         ^                         |
                         |                         v
                 allowlist 选中/文字提交 <── 页面原位交互
                         |
                         +── 右侧链接/图片设置
                         +── 高级字段表单

公开业务服务 ──> 动态 / 能力 / 经历 / 简历状态 ──> iframe 只读渲染

工作副本 ──严格校验──> 保存草稿 ──明确发布──> 正式首页
```

### 1. 无后台壳的受保护预览

将现有预览页从 `(workspace)` 路由组移到以下不使用 `AdminShell` 的独立路由组：

```text
src/app/admin/(preview)/home/visual-preview/page.tsx
```

URL 继续是 `/admin/home/visual-preview`。页面本身继续调用 `currentSession()`，未登录时拒绝访问；移动路由不会降低认证边界。

预览页先加载当前已保存草稿作为确定的初始内容，再使用与 `getPublicResumeData()` 相同的服务装配公开动态、公开能力、公开经历和公开简历下载状态。在 `public-resume.ts` 增加一个接受指定 `SiteContent` 的装配入口，共用现有公开列表服务和序列化逻辑；不要在预览路由复制过滤条件。

`HomeVisualEditor` 接收完整的 `PublicResumeData` 形状，并将其传给同一个 `HomeExperience`。未保存的快照文案由父页面实时覆盖，业务数据在 iframe 每次加载时刷新。这样既保持真实页面构成，也不会把私密记录或首页草稿误当成公开业务源。

### 2. 三栏专用工作区

`HomeWorkspace` 保留保存、发布、历史、刷新、脏状态和错误反馈职责。编辑区域改为三个顶级视图：

1. **可视化编辑**：左侧页面结构、中间真实首页、右侧选中项设置。
2. **字段编辑**：保留并扩展当前 `HomepageEditor`，作为键盘操作、集合维护、项目选择和预览失败时的备用入口。
3. **发布记录**：保留现有版本列表和“恢复为草稿”流程。

可视化视图中的三栏职责：

- **页面结构**：显示首屏、关于、当前动态、项目、能力、经历和联系。点击可滚动预览到对应区块；每项标明“本页文案可编辑”“来自业务模块”或项目这种混合来源。
- **真实预览**：iframe 保持正式首页样式。父级通过容器宽度提供桌面和手机两种设备预览，不复制一套页面组件。
- **选中项设置**：没有选中项时显示操作说明和保存状态；文字选中后显示字段名、语言和校验错误；链接显示目标输入；图片显示当前图片、替换操作和对应替代文本入口。

窄屏后台不强行压缩为三条窄栏，而把结构、预览和设置切换为三个页签。工作副本仍在父组件，切换面板不会丢数据。

### 3. 可编辑字段注册表

`visual-editor-protocol.ts` 继续作为唯一准入边界，但注册项补充：

- 字段路径；
- 类型：`text`、`link` 或 `image`；
- 所属页面区块；
- 中文标签；
- 是否只在右侧设置；
- 相关替代文本路径（图片字段）。

固定标量使用明确路径。段落、统计、技能、服务项和页脚链接等集合字段，由当前 `content` 枚举出具体存在的索引路径；检查的是生成后的精确路径，不接受任意点分隔对象路径，也不接受 `__proto__` 等属性。

页面组件只为快照拥有的字段输出编辑标记：

- `Navbar`：品牌和导航文字；目标锚点固定，不开放修改。
- `Hero`：角色、两行标题、介绍、按钮文字、人物图和人物图替代文本。
- `About`：眉题、标题、段落、统计、技能标签、工具箱文案和引语。
- `RecentWorks`：区块标题和动作文字；项目卡资料只读，回项目模块维护。
- `Services`：仅在没有结构化公开能力、实际显示回退内容时编辑首页快照文案。
- `Footer`：标题、介绍、菜单、社交文字、邮箱、GitHub、微信文字、二维码及替代文本。

动态、结构化能力、经历、简历状态和结构化项目资料不进入可编辑注册表。它们在页面结构中显示来源和管理入口，但 iframe 不得为其发送内容更新。

### 4. 原位编辑行为

- 点击或键盘聚焦可编辑文字时，iframe 发送 `select`，并用非纯颜色的轮廓显示当前字段。
- 文字在现有元素上使用受控的纯文本编辑；读取和提交均使用 `textContent`，绝不读取或保存 `innerHTML`。
- 输入过程中尊重 `compositionstart` / `compositionend`，避免中文输入法的中间状态被提前提交。失焦时提交最终纯文本；页面上的本地 DOM 已即时显示输入结果。
- 编辑模式中的链接点击用于选中，不执行页面跳转。页面内滚动按钮和语言切换仍可用；跨页、下载、表单提交和外部导航被阻止。
- GitHub 标签等可见链接文字在页面原位编辑；GitHub URL、邮箱地址在右侧面板修改。无效或未完成的目标在编辑预览中不生成可导航链接。
- 点击人物图或二维码只负责选中图片字段；右侧“替换图片”打开父页面的现有 `AssetPicker`。取消选择不改变工作副本。
- 图片说明继续存放在双语 `portraitAlt` / `wechatAlt` 字段，不从文件名自动生成。

### 5. 双语、设备与选中状态

父页面持有 `previewLocale`、`previewDevice` 和 `selectedField`：

- 中文或 English 切换只改变预览语言，不复制内容状态。
- 手机预览仅改变 iframe 外层宽度；页面仍走正式响应式 CSS。
- iframe 内的语言切换会把新语言回报给父页面，左右面板与页面保持一致。
- 同一路径在不同语言下是两个独立字段，选择和错误提示必须包含 locale。
- iframe 重载后，父页面重新发送当前语言、选中项和最新未保存内容；不能退回到已保存草稿。

## 编辑校验与保存校验分离

当前 `parseParentContentMessage()` 使用完整 `siteContentSchema`，因此用户暂时清空必填文字时，iframe 会拒绝整个新快照。阶段 2 将校验拆成三层：

1. **消息结构校验**：确认对象结构、字段类型、数组形状、长度上限和精确注册路径；允许编辑过程中出现空文字和未完成链接。
2. **编辑反馈校验**：继续使用严格规则生成字段错误，在页面和右侧面板提示；不丢弃用户输入。
3. **保存／发布校验**：`siteContentSchema`、媒体存在性和项目公开性仍是硬门槛；无效工作副本不能保存或发布。

编辑消息 schema 与保存 schema 由同一个 schema 工厂构造，避免维护两份可能漂移的对象形状。放宽只针对临时编辑值，不放宽以下边界：

- 图片仍只能由本地 `/images/...` 或现有 `/api/assets/{id}` 产生；可视化 UI 不提供任意路径输入。
- 非 HTTPS、脚本协议或未完成的链接在编辑预览中不可点击。
- iframe 只能提交注册过的纯文本字段；不能提交 HTML、样式或对象。
- 长度上限、数组形状、重复项目 ID 和原型链路径保护继续有效。

## 通信协议与生命周期

父页面到 iframe：

- `content`：当前编辑态内容、预览语言和当前选中路径；
- `focus`：滚动到允许的区块或字段。

iframe 到父页面：

- `ready`：本次 iframe 文档已安装消息监听；
- `select`：用户选择了一个注册字段；
- `commit`：一个注册文字字段提交了最终纯文本；
- `locale`：用户在页面内改变了语言。

双方必须同时验证：

- `event.origin === window.location.origin`；
- 父页面校验 `event.source === iframe.contentWindow`；
- iframe 校验 `event.source === window.parent`；
- 消息类型和 payload 通过对应解析器；
- 字段或区块存在于当前 allowlist。

父页面在 iframe `load` 时进入加载态。每次收到 `ready` 都直接从最新 state ref 发送完整工作副本，不依赖“ready 从 false 变 true”才能触发同步。内容、语言或选中项随后改变时继续同步。旧 iframe 发出的消息因 source 不匹配而被忽略。

## 保存、发布与历史边界

- 页面、右侧面板和高级表单都只更新同一个 `content` 工作副本。
- “保存草稿”沿用 `/api/admin/site/draft`；严格校验失败时保留输入、定位字段并说明原因。
- 独立“预览页面”继续用于检查已保存草稿，明确不包含未保存修改。
- “发布”继续要求内容有效且没有未保存修改；发布后正式首页和后台品牌图才更新。
- “恢复为草稿”替换工作副本前继续二次确认，不直接改变线上版本。
- 刷新后台数据前继续确认是否放弃未保存修改。重载 iframe 或切换可视化／字段视图不属于放弃修改。

## 后台品牌图回退

`AdminShell` 继续只接收最新已发布人物图，不读取未保存草稿。`BrandMark` 增加加载失败状态：

- 没有 `brandImage` 时显示 `17`；
- 图片触发 `onError` 时隐藏失败图片并显示 `17`；
- `brandImage` 属性改变时清除旧失败状态并尝试新图片。

不为小图生成第二套图片字段或独立上传入口。只有在实际流量测量证明原图体积不可接受时，再单独设计缩略图策略。

## 失败恢复与可访问性

- iframe 加载 10 秒仍未 ready、认证失效或渲染失败时，工作副本仍在父页面；显示“重试预览”和“转到字段编辑”，不清空数据。
- 无关窗口、错误来源或畸形消息静默忽略；只有来自预期 iframe 的可解释业务错误进入现有反馈区，避免恶意消息造成提示轰炸。
- 页面轮廓不能只靠颜色表达；所有可编辑元素可用键盘选中，并保持可见焦点。
- 右侧面板关闭媒体库后把焦点还给触发按钮或当前字段。
- 高级表单补齐四个 `settings` 字段及同一个媒体选择器，保证 iframe 不可用时仍能维护全部受支持内容。
- 原位编辑不改变正式页面的 accessibility tree；编辑标签只在 editor 模式出现。

## 组件职责

- `HomeWorkspace`：唯一工作副本、校验、脏状态、保存、发布、历史、预览生命周期和顶级视图。
- `HomepageVisualWorkspace`（新增）：三栏布局、结构导航、设备／语言控制、选中项设置和 `AssetPicker` 协调。
- `HomepageEditor`：完整字段备用入口，增加 `settings` 编辑；继续负责集合和项目选择，不复制保存逻辑。
- `HomeVisualEditor`：渲染真实 `HomeExperience`、处理页面内选择和纯文本提交，不调用管理 API。
- `visual-editor-protocol.ts`：字段注册、消息解析、允许的区块和编辑结构校验。
- `HomeExperience` 及公开区块组件：继续是正式页和编辑预览的唯一渲染组件；仅在 editor 模式附加标记和交互属性。
- `public-resume.ts`：唯一的公开首页业务数据装配逻辑，允许为受保护预览注入指定首页快照。

首版只新增一个三栏工作区组件；结构树和简单设置面板可以先作为其内部区域。只有当实现后职责确实过大时才继续拆分，避免为单一页面建立通用编辑框架。

### 浏览器验收

在本地受控数据库和已登录后台完成以下矩阵，并将结果记录到阶段计划，而不是仅凭测试通过勾选 F2：

1. 桌面和手机预览均无后台壳，区块、顺序和正式首页一致。
2. 中文和 English 分别编辑标题、段落、按钮及链接文字；验证中文输入法、粘贴纯文本、失焦提交。
3. 修改 GitHub／邮箱目标；无效中间值保留但不可点击、不可保存。
4. 从媒体库替换人物图和二维码，验证选择、取消、替代文本、缺失资源错误。
5. 在未保存状态下切换语言、设备、字段视图，重载 iframe 并点击重试；修改仍在。
6. 保存后独立预览可见，正式首页仍不变；发布后正式首页更新。
7. 恢复历史版本只生成草稿，确认后发布才影响正式首页。
8. 强制品牌图片加载失败，桌面侧栏和手机顶栏都显示 `17`。
9. 模拟预览认证失效或加载失败，高级表单仍可编辑、保存和恢复。

### 完成前命令

实施完成后运行聚焦测试、完整 `npm test`、`npx tsc --noEmit`、`npm run lint`、`npm run db:validate`、使用临时数据库的生产构建，以及 `git diff --check`。本地通过、功能分支推送、合并、部署和线上验收必须分别记录。

## 实施顺序原则

书面设计批准后，实施计划应按以下依赖拆分，而不是同时大改所有页面：

1. 先统一真实预览的数据装配并移除后台壳，建立 B1 基线。
2. 再修正编辑态 schema 和通信生命周期，保证无损同步与安全边界。
3. 扩充页面标记和选中态，完成文字、链接、图片三种编辑。
4. 将界面收敛为三栏工作区，并把高级表单改为备用视图。
5. 最后补品牌图失败回退、异常恢复、自动化测试和完整浏览器矩阵。

每一步都必须保留现有保存与发布能力。阶段 2 不夹带知识库入口、独立简历入口、重复行动、仪表盘待办中心或 C1–C5。

## 不在本阶段

- 任意区块增删、拖拽排序或布局模板。
- 撤销／重做、自动保存、多人协作、评论、审批和插件系统。
- 任意 HTML、Markdown、CSS、JavaScript 或 DOM 持久化。
- 在首页画布直接修改动态、能力、经历、项目资料、简历文件或媒体元数据。
- 知识库固定入口、独立简历入口及其他公共导航改造。
- 合并、部署、数据库迁移或生产数据修复。

## 设计自查

- 无占位内容；字段归属、保存目标和生效时机均已明确。
- 架构保持单一快照和现有发布流程，没有引入通用页面构建器或第二套持久化。
- 编辑态允许临时无效值，但危险链接、图片来源、任意路径和 HTML 边界没有放宽。
- 自动化测试与人工浏览器验收分开，未把源码字符串断言当作交互闭环。
- 范围覆盖 B1–B9，明确排除尚未批准的 C1–C5 和后续业务入口工作。
