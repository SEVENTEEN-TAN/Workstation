# 功能优化计划审查摘要与执行边界

本文件随功能分支保存审查结论与后续执行边界。主项目同名文档保留更完整的历史静态审查、源码行号和证据。审查基线：main `eaa6750`，功能分支 `926790e`；历史结论不代表修复已完成。

结论：旧首页计划不能直接覆盖全部 30 项 TODO。后续按任务已授权的分阶段方式推进；C 组新增低代码能力仍待确认，部署仍需另行授权。

## 六项重要问题

1. **范围不一致**：旧计划只有首页编辑，新 TODO 还含数据保护、OKR、入口、仪表盘与待确认扩展。每项必须映射任务包和验收条件，不能静默扩大范围。
2. **预览不等于正式前台**：旧嵌入页位于后台 workspace 布局中，且缺少动态、能力、经历和简历状态。需要不带后台壳、受认证保护的预览，并复用正式页公开数据规则。
3. **编辑态与保存校验混用**：完整 schema 校验会拒绝清空必填字段等临时值。需分开安全结构校验、编辑错误提示和保存／发布校验，不放宽危险链接或任意路径。
4. **同步生命周期不足**：双方须验证 origin 和来源窗口；每次 ready／load 都同步最新编辑态；视图切换、重载、重试与认证失效不能导致输入丢失。
5. **字段归属未定义**：逐字段列出来源、编辑方式、保存目标和生效时机。首页快照与实时业务记录不同；草稿编辑不能意外修改公开源记录。
6. **测试示例不可执行且覆盖不足**：旧计划含不存在的测试助手及接口漂移。应基于实际接口验证输入法、链接、媒体、切换、重载、保存、发布、恢复和认证；源码字符串断言不能代替操作验收。

## 必须保留的边界

- 旧计划按历史文档规则保持原样；另建日期计划，不回填旧复选框。
- 弹窗居中已有 `98e60e4`，只补真实浏览器验收；不重复实现或宣称线上修复。
- 图片设置及头像复用、iframe 和首屏文字已有部分实现；从实际差距续作，不从零重建。
- C1–C5 不默认为已批准。C5 的单一数据来源原则可以作为约束，但不代表批准新的画布编辑能力。
- 头像缺失回退不等于图片加载失败回退；须分别验收。
- 公开条件说明复用前台判断，不另写可能漂移的规则，不为了预览混入私密记录。
- 周报候选采用、未保存输入、并发修改需要一起设计；重复行动先明确时区、截止日算法、重开和幂等规则。
- 生产异常记录先只读核查，数据修复另行确认；首页历史恢复不等于回滚业务源记录。
