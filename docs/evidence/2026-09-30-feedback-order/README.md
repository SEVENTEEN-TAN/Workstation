# 并发操作提示与旧扫描验收

日期：2026-09-30。独立 Temp SQLite、真实 Next API 与 Edge；未合并、部署或操作生产数据。

## 已确认问题与修复

共享 `useAdminAction` 只有一条提示。扫描与发布、下架、审核使用不同操作锁，允许同时进行：旧扫描晚于新发布失败返回时会用成功提示覆盖错误；旧扫描在新发布等待期间完成时，其四秒成功计时器又会清掉随后出现的错误。旧扫描也会替换较新的发布、下架、审核成功提示。

修复仅在共享 hook 增加操作序号：只有最近发起的操作更新提示和计时器。较旧操作仍返回结果、执行调用方数据合并、释放自己的锁；同 key 去重保持原有语义。该设计仍是一条提示，不是每个并发操作的通知记录。

扫描先在服务器真实执行并取得JSON，再挂起返回浏览器；发布失败在服务器执行前返回可识别的注入500。两个拦截器在任何操作前一次登记，运行中不修改拦截模式，避免浏览器自动放行已挂起请求。成功发布、下架和审核均使用实际API，响应分别201/200/200。未替换成功操作响应中的业务数据。
